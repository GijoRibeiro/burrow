# Product review and roadmap — October 2026

A full-codebase review of Burrow (still shipping as Cloovies) against the goal of an Orca-class desktop workspace: many terminals and agents, visible at a glance, reliably alive. Findings come from reading every workspace package, running the Go, unit, race and 41-scenario browser suites on macOS 26, and comparing with Orca 1.4.197.

The first section records what was fixed in this pass. The rest is the ordered backlog, each item with the file to start in.

## Backlog, in order

### 1. Make it a product people can download and trust

1. **Developer ID signing, hardened runtime, notarization, stapling** in `scripts/package-workspace-app.sh`; without it every install is a right-click-open and folder permissions flap between builds (`docs/MACOS-UPDATES.md` describes the symptom).
2. **In-app updates.** The legacy app had Sparkle with EdDSA keys; port that to `app/workspace.swift` with an appcast published alongside the release zip. The version handshake added in this pass is the prerequisite.
3. **CI.** No `.github/workflows` exist. One macOS workflow running `go test ./...`, `npm test`, `npm run test:workspace`, `python3 scripts/test-workspace-installer.py`, and the package script on tags.
4. **One name.** Burrow in the README, Cloovies in the bundle, bitwise in the Makefile, `burrow` and `BURROW_*` for the agent CLI, `~/.cloovies` on disk. Pick Burrow, rename the bundle ID once with a tested migration of `~/.cloovies` and the tmux socket, and delete the bitwise Makefile targets.
5. **Delete or quarantine the legacy tree.** `cmd/bitwise`, `cmd/clooviesd`, `cmd/cloovies`, `internal/{server,scanner,chat,boss,orchestrator,registry,workers,terminal,tui,sprites,store,config}` and `web/src/main.ts` plus `ui/`, `canvas/`, `world/` are roughly half of all code, all built, tested and shipped inside the binary. Move them to a `legacy/` branch or module.
6. **Diagnostics.** A "Copy diagnostics" action (versions, tmux version, PATH, last log lines, terminal count) and a documented bug-report path.

### 2. Reliability still open

1. **Worktree and team operations still exec git under `m.mu`** (`model.go createWorktreeLocked`, `coordination.go delegate`, `teams.go StartPlan`, `IntegrateTask`). Apply the same prepare/launch split with a placeholder record; a 6-worker plan on a large repo currently blocks the API for tens of seconds.
2. **Snapshot cost.** Every 3 s poll runs `tmux list-panes`, `git worktree list` per project, and when Claude runs, `ps` plus a read of every `~/.claude/sessions/*.json`. Replace polling with a push channel: a `/api/workspace/events` WebSocket fed by tmux hooks (`session-created`, `pane-died`, `client-resized`) and a filesystem watcher on `.git/worktrees`, with the current poll as fallback.
3. **Reboot recovery.** After a reboot everything is Stopped. Add "Start all stopped agents" and an optional "resume agents on launch" setting; resume now works, so this is one loop in `app.ts`.
4. **Orphan reconciliation.** `cw-*` tmux sessions without a workspace record (a failed save, a replaced state file) are invisible. List them at startup and offer adopt or kill in the sidebar.
5. **Corrupt state file aborts startup** (`model.go New`). Back the file up, start with what parses, and surface the problem in health and the UI instead of `log.Fatal`.
6. **Typed errors.** Every API error is HTTP 400. Distinguish not-found, unavailable (tmux missing) and timeout so the UI can offer the right action.
7. **Input typed while reconnecting is dropped silently** (`terminal.ts input()`). Buffer a few KB and flush on open, or flash the connection badge.
8. **Hidden-pane cache keeps eight live tmux clients.** With `window-size latest` a hidden client can shrink the visible one; close hidden sockets and reattach on show now that scrollback survives reattach.
9. **Large paste over 1 MiB closes the socket** (`SetReadLimit`). Chunk on the client.
10. **Login-shell PATH.** GUI apps do not see shell-profile PATH changes; MacPorts, cargo, volta and npm-global installs of `claude` are reported missing. Run `$SHELL -lc 'echo $PATH'` once at daemon start and merge it (`internal/env/path.go`).

### 3. Every agent interaction from the chat view

The goal stated for this product is that a user never has to drop to the raw terminal to deal with an agent. Today chat covers text, images, local image previews, links, slash commands (which open the terminal) and interrupt. Still missing:

1. **Choice prompts.** Claude's `AskUserQuestion` and Codex's approval and multiple-choice prompts render only in the terminal. Detect them from the screen buffer (the parser in `agent-view.ts` already recognises interactive prompts) and render buttons in chat that send the matching keys.
2. **Plan approval and permission prompts** when a user turns YOLO mode off; today both agents are launched with permissions bypassed and there is no per-agent toggle. Offer a per-terminal "ask before acting" mode and render the prompts in chat.
3. **Attention signals outside the window.** No dock badge, no notification, no menu-bar item. Add a `notify` script-message handler in `workspace.swift` that sets `dockTile.badgeLabel` and posts a `UNUserNotification` when an agent is waiting and the window is not key; show a "needs you" marker in the sidebar and the picker.
4. **Links and files.** Terminal links now open; next, make file paths in both views clickable (open in editor, or preview diffs) and render agent-produced Markdown files and images inline.
5. **Conversation search and jump-to-turn** across the paged history, and copy-as-Markdown for a reply.
6. **Transcript export** when removing an agent, and a confirmation before killing a running one.
7. **Live status for Codex.** `LiveStatus` (working/idle/waiting) exists only for Claude; Codex has the same information in its rollout events.
8. **Status cards.** The team canvas is the visual overview; add a compact "all agents" strip in the terminal view showing each agent's state, last message and elapsed time, like Orca's worktree cards.

### 4. Parity with Orca worth copying

| Orca feature | Suggested shape here |
| --- | --- |
| Repository setup hooks (post-create scripts, terminal defaults) | Per-project `setup` command run in a new worktree's first terminal; stored in `workspace.json` |
| Worktree cards with status, comments and lineage | Extend the team canvas cards to every worktree, with dirty/ahead/behind from `git status --porcelain=2 --branch` |
| Scheduled automations | A cron-like table executed by the daemon into a new worktree with a chosen agent; the complaint scanner is already a scheduler to generalise |
| Embedded browser per worktree | A WKWebView pane type pointed at the detected dev server (`servers.go` already finds ports) |
| Documented CLI for everything | `internal/agentcli` covers coordination only; add `burrow terminal list/send/read/wait` and `burrow worktree create` and document them |
| Managed accounts and remote environments | Out of scope until the local product is solid |

### 5. Code health

- `app.ts` (1500 lines) mixes store, layout, dialogs and team orchestration; extract `WorkspaceStore`, `LayoutController`, `TeamController`.
- `terminal.ts` (1000 lines) should split into `TerminalConnection` (socket, reconnect, keepalive) and `Composer`.
- `MutationObserver` on `document.body` with `subtree: true` fires on every xterm frame (`app.ts` toolbar measurement); observe only dialogs.
- `persist()` runs on every keystroke; debounce.
- `go.mod` lists direct dependencies as indirect; run `go mod tidy`.
- `web/dist` bundles the legacy dashboard (`legacy-*.js`, 160 kB) into the app.
